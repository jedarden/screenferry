# bf-421: Enforce §16.3's version refusal in readPacket

**Status:** ✅ Already implemented (commit 68a930ff, 2026-08-02)

## Implementation

The §16.3 version refusal requirement has been fully enforced in `readPacket()`:

### Current Implementation (src/core/frame/header.ts:75-85)

```typescript
// §16.3: Refuse packets with unknown wire version - never attempt a partial parse.
// The header's 4-bit nibble is a fast reject; the beacon's 1-byte wireVersion is
// authoritative. When the nibble doesn't match, we must report E-VERSION and refuse.
const wireVersion = bytes[0]! & 0x0f;
if (wireVersion !== (WIRE_VERSION & 0x0f)) {
  throw new PacketVersionError(
    'E-VERSION',
    `Wire version mismatch: sender is ${wireVersion}, receiver is ${WIRE_VERSION}`,
    { senderVersion: wireVersion, receiverVersion: WIRE_VERSION }
  );
}
```

### Key Features

1. **Fast reject**: Checks version nibble before any other parsing
2. **Proper error reporting**: Throws `PacketVersionError` with code `'E-VERSION'`
3. **Detailed context**: Includes both sender and receiver versions in error details
4. **No partial parse**: Throws immediately without attempting CRC or payload parsing
5. **Tested**: codec.test.ts validates this behavior with test "rejects unknown wire version per §16.3"

### Compliance with §16.3

✅ Receiver seeing unknown version reports E-VERSION  
✅ Refuses to parse packet (throws, never returns partial data)  
✅ Never attempts partial parse (throws before CRC check)  
✅ Shows both versions in error message  

The implementation exactly matches the §16.3 requirement: "A receiver seeing an unknown version MUST report E-VERSION with both versions shown and refuse — never attempt a partial parse."
